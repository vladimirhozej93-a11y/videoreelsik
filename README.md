# Лидофлоу — личная CRM Владимира

Подготовленный перенос интерфейса из Sites в Cloudflare Workers + D1. Публикация и перенос реальных данных ещё не выполнены.

## Что сохранено

- Обзор, база компаний, таблица и канбан, фильтры и поиск.
- Карточки, статусы, контакты, бюджет от 5 000 ₽, история откликов.
- Поиск на внешних площадках и шаблоны сообщений.
- Напоминания внутри открытой CRM и выгрузка JSON.
- Мобильный интерфейс и исходное оформление.

Вход теперь по отдельному паролю; ChatGPT для работы не нужен. Пароль хранится только как секрет Cloudflare `CRM_PASSWORD`. Клиентские данные хранятся в D1, а не в браузере. До настройки пароля и базы API закрыт. Сессия хранится в HttpOnly Secure cookie на 7 дней. После смены пароля предыдущие сессии перестают работать; кнопка «Выйти» удаляет cookie на текущем устройстве.

## Публикация из терминала

Нужны бесплатный аккаунт Cloudflare и Node.js 22.13+ (лучше 24 LTS). Платный Workers и свой домен не требуются. Использование остаётся бесплатным в пределах Free; проверьте текущие лимиты в своём аккаунте.

1. Распакуйте архив и откройте папку в терминале.
2. `npm ci`
3. `npm run setup`
4. `npm run deploy`

Setup открывает вход Cloudflare, создаёт базу `leadflow-db`, запрашивает её `database_id`, применяет схему и предлагает скрыто ввести пароль CRM. Используйте уникальную случайную строку от 16 символов (например, 24 символа из менеджера паролей). Не отправляйте пароль или API-токены в переписку.

После deploy откройте адрес `workers.dev`, который напечатает Wrangler, и войдите паролем CRM. Точное имя адреса выдаёт Cloudflare. Публиковать страницу без защиты API нельзя. Исходники не содержат паролей, токенов и клиентской базы.

## Если подключать с телефона через GitHub

Проект нужно поместить в отдельный репозиторий GitHub, затем подключить его в Cloudflare Workers & Pages. Команда сборки: `npm ci && npm run build`. Команда публикации: `npx wrangler deploy`. Корень проекта: `/`.

Перед публикацией создайте базу D1 `leadflow-db`, скопируйте её UUID в `wrangler.jsonc` вместо `REPLACE_WITH_D1_DATABASE_ID` и выполните SQL из `migrations/0001_initial.sql` в консоли этой базы. У опубликованного Worker должна быть привязка `DB` к этой базе. Добавьте секрет `CRM_PASSWORD` от 16 символов в настройках Worker и примените настройки. Публичная оболочка страницы не содержит клиентских данных; API до задания секрета отвечает 503.

Через GitHub можно обновлять CRM без постоянно включённого компьютера. Для первичной настройки аккаунта и прав подключения нужны действия владельца. Подключение через GitHub и публикация из этого архива пока не выполнены.

## Локальная проверка

1. `npm ci`
2. `npm test`
3. `npm run build` и `npm run test:runtime`
4. Создайте локальный `.dev.vars` с `CRM_PASSWORD="ваш-локальный-тестовый-пароль-от-16-символов"`.
5. `npx wrangler d1 migrations apply DB --local`
6. `npm run preview`

Откройте локальный адрес Wrangler. Secure cookie работает на localhost; для удалённого доступа используйте HTTPS. `.dev.vars` не включайте в Git и архивы. Продакшен-пароль для локальных тестов не используйте.

## Существующие данные

Этот архив переносит код, а не базу Sites. Он не содержит реальных клиентов. Для миграции существующих записей сначала нужна отдельная выгрузка JSON из старой CRM. Не очищайте старую базу, пока перенос не проверен. Демонстрационные карточки — примеры; они не записываются в базу автоматически.

## Ограничения

Напоминания отображаются внутри CRM при открытии; фоновые пуши и Telegram не подключены. Поиск открывает внешние площадки; автоматического сбора и отправки сообщений нет. JSON-выгрузка служит резервной копией, интерфейс импорта в этой версии отсутствует. После выхода локально уже выгруженный JSON остаётся на устройстве пользователя.

## Проверка перед передачей

Сборка с проверкой TypeScript и 9 автоматических проверок API прошли. Упаковка Wrangler в режиме dry-run прошла. В Miniflare (среда исполнения Workers) проверены выдача страницы, вход и сохранение, повторная загрузка и удаление карточки в D1. Локальная проверка страницы в браузере не завершена: сервер Wrangler в этой среде не запустился из-за `uv_interface_addresses`; это ограничение локального запуска, а не подтверждённая ошибка опубликованного сайта. Публикация в реальном аккаунте Cloudflare требует входа владельца.

## Поиск организаций Яндекс Карт

В разделе «Поиск заказов» доступен поиск через официальный API: ниша, город, до 50 результатов за запрос и следующие страницы. Для подключения задайте секрет `YANDEX_MAPS_API_KEY` в Cloudflare Worker, окружение Production, и примените его через Deploy. Ключ в GitHub и переписку не отправляйте.

На сервере действует ограничение 100 запросов из этой CRM в сутки по Москве. Счётчик не отражает обращения из других приложений с тем же ключом. Ошибочные попытки после отправки тоже учитываются, автоматических повторов нет. Для схемы счётчика применяется миграция `0002_yandex_usage.sql` действующей командой развёртывания.

API-ключ не попадает в браузер. Поисковые запросы и ответы API не кэшируются в D1 или localStorage; выбранная компания сохраняется отдельно как лид после проверки и подтверждения пользователя. Порядок выдачи сохраняется. Автоматическое сохранение всей выдачи и ежедневный сбор в этой версии не включены. Для постоянного хранения данных следует подтвердить соответствующее право по лицензии Яндекса. Сам по себе пробный API не создаёт автоматический сбор по расписанию.

## Интерфейс 1.1

Компактная навигация для узкого окна и телефона, поиск по всей базе (⌘/Ctrl+K), добавление компании клавишей N, Escape для закрытия панели и ограничение Tab внутри открытого диалога. Открытый раздел сохраняется в адресе; результаты Яндекс-поиска остаются в памяти вкладки при переключении разделов и сбрасываются после обновления страницы. Быстрая форма содержит телефон и Telegram. Выход находится в профиле и не перекрывает интерфейс.

Визуальные ориентиры: Atomic CRM (marmelab/atomic-crm) и TailAdmin (TailAdmin/free-react-tailwind-admin-dashboard). Код этих проектов не переносился. Оформление и поведение реализованы в текущем приложении без новых зависимостей.

### Личная CRM и отдельные клиентские установки

Текущая версия имеет одного владельца (`vladimir`), общую базу и один пароль. Она не поддерживает независимые аккаунты клиентов, роли, оплату подписки или изоляцию арендаторов. Для отдельной установки каждому клиенту нужны собственные Worker, D1, секреты и разрешённые интеграции. Совместный доступ по одному паролю даст доступ к одной базе. Многопользовательская коммерческая версия требует отдельной реализации авторизации, изоляции данных, ролей, оплаты и управления подписками; подключение Яндекс API оплачивается и лицензируется отдельно.

## Перенос результата поиска в лиды

Кнопка «В лиды» у результата поиска открывает заполненный черновик: название, ниша, город, телефон, сайт, адрес и ссылка на Яндекс Карты. Наличие данных зависит от ответа Яндекса. Рейтинг и бюджет не считаются подтверждёнными. Сохранение происходит после проверки и нажатия «Сохранить компанию». Фоновый сбор и массовый импорт по расписанию не включены. При сохранении данных нужно соблюдать условия используемой лицензии Яндекса.

Сохранённый идентификатор организации проверяется сервером и уникальным индексом D1 в пределах владельца. Повторное добавление открывает уже существующую карточку. Для ранее добавленных вручную компаний интерфейс также сверяет телефон, название и город. Разные идентификаторы филиалов автоматически не объединяются. Схема расширяется миграцией `0003_yandex_lead_identity.sql`; существующие ручные записи сохраняются.
